# 15. PCA in Code

Now we implement PCA.

A common Python/scikit-learn workflow is:

```python
from sklearn.decomposition import PCA

pca = PCA(n_components=2)

pca.fit(X)

X_reduced = pca.transform(X)
```

The important functions are:

### `fit(X)`

Learns the principal components from the dataset.

### `transform(X)`

Projects the original data onto those components.

So:

```text
X
↓
pca.fit(X)
↓
learn important directions
↓
pca.transform(X)
↓
X_reduced
```

The course notes also demonstrate checking the **explained variance ratio**, which tells us how much of the original variation each principal component captures. ([Scribd][3])

For example:

```text
PC1 → 70%
PC2 → 20%
PC3 → 5%
PC4 → 5%
```

Then the first two components preserve:

$$
70\%+20\%=90\%
$$

of the variance.

So we might keep only those two.

---

## ⚠️ One important preprocessing point

Before PCA, the features generally need to be **centered**, and when features have very different scales, **feature scaling** is important. The DeepLearning.AI course discussion specifically notes zero-mean preprocessing and comparable feature ranges for PCA. ([DeepLearning.AI][4])

For example:

```text
Age       → 18–80
Income    → 20,000–2,000,000
```

Income would dominate purely because its numerical scale is much larger.

# 🧠 The entire PCA concept

Remember this simple flow:

```text
Many features
     ↓
Remove redundant dimensions
     ↓
Find important directions
     ↓
Project data onto them
     ↓
Fewer dimensions
```

Mathematically:

$$
\boxed{X \rightarrow Z}
$$

where \(X\) is the original high-dimensional data and \(Z\) is the lower-dimensional representation.

### The most important distinction

**Feature selection:**

> Keep some of the original features.

**PCA:**

> Create new features called **principal components** from combinations of the original features.

That's a very important distinction to remember.
