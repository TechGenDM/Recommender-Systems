## 3. Collaborative Filtering Algorithm

Now we reach one of the **most important ideas in recommender systems**.

The key trick is:

> **Instead of manually telling the system what each movie's features are, let the algorithm learn the features from users' ratings.** ([Coursera][1])

### Let's start with a movie-rating table

Suppose we have:

| Movie   | Alice | Bob | Charlie |
| ------- | ----: | --: | ------: |
| Movie A |     5 |   5 |       1 |
| Movie B |     4 |   4 |       2 |
| Movie C |     1 |   1 |       5 |

We notice that Alice and Bob have similar tastes.

But we **don't explicitly tell the algorithm**:

> "Movie A is romantic, Movie C is action."

Instead, the algorithm tries to **discover hidden features** that explain the ratings.

---

### User preferences

For each user, we learn a parameter vector:

$$
w^{(j)}
$$

For example:

$$
w^{(Alice)}=
\begin{bmatrix}
5\\
0
\end{bmatrix}
$$

Maybe the two hidden features are something like:

* \(x_1\) = romance
* \(x_2\) = action

Alice strongly likes romance and doesn't care much about action.

But here's the clever part:

### The movie features are also unknown

Previously we had:

$$
\hat y^{(i,j)}
=
w^{(j)}\cdot x^{(i)}+b^{(j)}
$$

Earlier, we treated \(x^{(i)}\) as something we already knew.

In **collaborative filtering**, we don't necessarily know those \(x\)'s.

The algorithm learns:

$$
\boxed{w^{(j)},\ b^{(j)},\ x^{(i)}}
$$

**all together** from the ratings.

That's the heart of collaborative filtering.

---

### Why is this possible?

Imagine thousands of users rating thousands of movies.

If many users who love certain movies consistently give high ratings to another group of movies, the algorithm can discover a hidden pattern.

So it might automatically learn something like:

```text
Hidden feature 1 → romance
Hidden feature 2 → action
Hidden feature 3 → comedy
...
```

You didn't explicitly label these features.

The model **discovers them from the collaborative behavior of users**.

That's why it's called:

> **Collaborative filtering** — it uses information from many users' preferences to help make recommendations. ([Coursera][1])

---

### The prediction

For user \(j\) and item \(i\):

$$
\boxed{
\hat y^{(i,j)}
=
w^{(j)}\cdot x^{(i)}+b^{(j)}
}
$$

The model tries to make this predicted rating close to the user's actual rating.

Conceptually:

$$
\text{Actual ratings}
\rightarrow
\text{learn user preferences + item features}
\rightarrow
\text{predict missing ratings}
$$

### 🧠 The most important distinction

**Content-based approach:**

> "I know what the item is like → predict whether the user will like it."

**Collaborative filtering:**

> "I know how many users have interacted with items → discover patterns in those interactions and predict what this user will like."

And this is why collaborative filtering can discover useful item features **without us manually defining them first**. ([DeepLearning.AI][2])
